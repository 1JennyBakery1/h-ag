    从 LLM 训练到 Agent RL

    当 Agent 面对复杂的、多步骤的任务时——如数学推理、工具编排、迭代规划——原始的提示词和监督式模仿会暴露出三个结构性局限：数据质量天花板（模型只能复制训练模式）、零探索（无法发现更优的推理路径）和脆弱的泛化能力（在分布偏移下，确定性模仿会失效）。Agent RL 将 LLM 重新定义为序列决策循环中的可学习策略，其中 Agent 与环境交互，在每一步接收反馈，并以累积任务完成为优化目标，而非单轮回答质量。

    MDP（马尔可夫决策过程）的形式化体系与该范式完美契合：Agent 是 LLM 策略，环境 是任务加上验证系统，状态 是当前上下文和推理历史，动作 是生成下一个推理步骤或工具调用，而奖励 则标志着任务进度。这是从 PBRFT（基于偏好的强化微调）到 Agent RL 的根本性转变：前者优化单步期望奖励 JPBRFT(θ)=Es0,y∼πθ[r(s0,y)]J_{\text{PBRFT}}(\theta) = \mathbb{E}_{s_0, y \sim \pi_\theta} [r(s_0, y)]JPBRFT​(θ)=Es0​,y∼πθ​​[r(s0​,y)]，而后者最大化累积折扣奖励 JAgentic(θ)=Eτ∼πθ[∑t=0Tγtr(st,at)]J_{\text{Agentic}}(\theta) = \mathbb{E}_{\tau \sim \pi_\theta} \left[\sum_{t=0}^{T} \gamma^t r(s_t, a_t)\right]JAgentic​(θ)=Eτ∼πθ​​[∑t=0T​γtr(st​,at​)]，其中 τ=(s0,a0,s1,a1,...,sT)\tau = (s_0, a_0, s_1, a_1, ..., s_T)τ=(s0​,a0​,s1​,a1​,...,sT​) 是完整轨迹。

    Agent RL 的六大核心能力

    Agent RL 旨在培养六项能力，将语言模型从被动的文本生成器转变为自主 Agent：

    • 推理：学会分解问题，并发现超越训练数据模仿的全新解决路径。
    • 工具使用：扩展动作空间以包含结构化的工具调用 attool=(tool_name,arguments)a_t^{\text{tool}} = (\text{tool\_name}, \text{arguments})attool​=(tool_name,arguments)，学习何时以及如何调用外部能力。
    • 记忆：优化上下文管理策略——存储、检索和丢弃哪些信息——而非依赖静态 RAG。
    • 规划：学习带有回溯的动态非线性规划，而非遵循线性的思维链模板。
    • 自我改进：开发自我反思循环，以识别错误、分析失败原因并调整策略。
    • 感知：扩展至多模态理解，学习利用视觉工具和视觉规划。

    HelloAgents 的 Agent RL 架构

    HelloAgents 框架通过四层架构实现 Agent RL，集成了 TRL (Transformer Reinforcement Learning) 库与 Qwen3-0.6B 模型。TRL 提供了成熟稳定的强化学习原语；Qwen3-0.6B 则提供了一个紧凑而强大的基础模型，适合消费级 GPU。

    数据集层 通过 GSM8KDataset、create_sft_dataset() 和 create_rl_dataset() 处理数据加载与格式转换。奖励函数层 提供 MathRewardFunction 作为基类，包含三种内置奖励实现。LoRA 层 管理参数高效微调配置。训练层 编排来自 TRL 的 SFTTrainer 和 GRPOTrainer。

    数据集与奖励函数

    数据集定义了 Agent 学习什么；奖励函数定义了什么是良好行为。两者共同构成了强化学习训练流程的两大基石。

    GSM8K：数学推理基准

    GSM8K (Grade School Math 8K) 是主要的训练数据集——包含 7,473 个训练样本和 1,319 个测试样本，均为需要多步推理的小学数学应用题。数学问题非常适合强化学习训练，因为它们具有明确无误的正确答案（无需人工标注或奖励模型即可实现自动化奖励计算）、组合结构（需要逐步分解）和可扩展的难度。

    根据训练阶段的不同，数据集必须转换为两种不同的格式：

    SFT 格式 — 包含完整的解题过程，用于监督式模仿：

    RL 格式 — 仅提供问题和真实答案；模型必须自己生成推理过程：

    关键区别在于：SFT 格式通过示例教导模型如何推理；RL 格式则迫使模型发现推理路径，仅以奖励作为引导。

    内置奖励函数

    HelloAgents 提供了三种可组合的奖励函数，每种都具有独特的信号特征：

    racc(a,a∗)={1if a=a∗0otherwiser_{\text{acc}}(a, a^*) = \begin{cases} 1 & \text{if } a = a^* \\ 0 & \text{otherwise} \end{cases}racc​(a,a∗)={10​if a=a∗otherwise​

    简单明确，但对于“几乎正确”的答案无法提供梯度。最好作为基础奖励，与更密集的信号结合使用。

    (2) 长度惩罚 — 在保持正确性的同时对冗长进行正则化：

    rlength(a,a∗,l)=racc(a,a∗)−α⋅max⁡(0,l−ltarget)r_{\text{length}}(a, a^*, l) = r_{\text{acc}}(a, a^*) - \alpha \cdot \max(0, l - l_{\text{target}})rlength​(a,a∗,l)=racc​(a,a∗)−α⋅max(0,l−ltarget​)

    惩罚仅在答案正确时适用，防止模型通过生成简短的错误答案来钻系统空子。默认 α=0.001\alpha = 0.001α=0.001，ltargetl_{\text{target}}ltarget​ 可配置。

    (3) 步骤奖励 — 鼓励可解释的、结构化的推理：

    rstep(a,a∗,s)=racc(a,a∗)+β⋅sr_{\text{step}}(a, a^*, s) = r_{\text{acc}}(a, a^*) + \beta \cdot srstep​(a,a∗,s)=racc​(a,a∗)+β⋅s

    其中 sss 是检测到的推理步骤数（通过 "Step N:" 标记或模式匹配）。步骤奖励仅在答案正确时给予，防止通过生成虚假步骤来进行奖励作弊。默认 β=0.1\beta = 0.1β=0.1。

    自定义数据集与奖励函数

    对于特定领域的任务，框架支持数据集的三种扩展路径：(1) 通过 format_math_dataset() 从原始 {question, answer} 对自动转换，(2) 通过 custom_dataset 参数直接传入，(3) 通过 rl_tool.register_dataset() 注册可复用的数据集。自定义奖励函数必须遵循签名 def custom_reward(completions: List[str], **kwargs) -> List[float]，其中 kwargs 通常包含 ground_truth。它们可以直接传入，或通过 rl_tool.register_reward_function() 注册。

    在设计自定义奖励函数时，考虑提供部分分数（例如，接近正确答案时 r=0.8r=0.8r=0.8，方法正确但计算错误时 r=0.5r=0.5r=0.5），而非纯粹的二元信号。部分分数能创造更密集的奖励景观，从而稳定 GRPO 训练，尤其是在生成组较小的情况下。

    SFT 训练：奠定基础

    SFT 是不可或缺的第一步。如果没有它，预训练模型会产生冗长且无结构的输出，无法被解析用于奖励计算——这使得 RL 训练无法进行。SFT 教会模型三件事：输出格式化（使用 "Step 1"、"Final Answer:" 标记）、推理模式（逐步分解问题）和基础能力（在 Qwen3-0.6B 上的 GSM8K 准确率达到约 40-50%，而基础模型几乎无法产生结构化输出）。

    GRPO 训练：优化推理策略

    SFT 产生的是一个模仿训练数据推理模式的模型。GRPO 则使模型能够通过探索和奖励引导的优化来发现更优的策略。核心洞见在于：SFT 教会模型好的答案看起来什么样；GRPO 教会它如何找到好的答案。

    从 PPO 到 GRPO：消除价值模型

    经典的强化学习算法 PPO 需要一个独立的价值模型来估计优势函数 A(s,a)=Q(s,a)−V(s)=r(s,a)+γV(s′)−V(s)A(s,a) = Q(s,a) - V(s) = r(s,a) + \gamma V(s') - V(s)A(s,a)=Q(s,a)−V(s)=r(s,a)+γV(s′)−V(s)。这使内存需求翻倍，并因价值模型自身的估计误差引入了训练不稳定性。

    GRPO (Group Relative Policy Optimization，组相对策略优化) 完全消除了价值模型，用组相对奖励代替了绝对优势估计。对于每个问题，模型生成 NNN 个候选答案，接收奖励 r1,...,rNr_1, ..., r_Nr1​,...,rN​，并计算相对奖励 r^i=ri−rˉ\hat{r}_i = r_i - \bar{r}r^i​=ri​−rˉ，其中 rˉ=1N∑i=1Nri\bar{r} = \frac{1}{N}\sum_{i=1}^{N} r_irˉ=N1​∑i=1N​ri​。

    方面PPOGRPO
    所需模型策略 + 价值 + 参考仅策略 + 参考
    优势估计A(s,a)=r+γV(s′)−V(s)A(s,a) = r + \gamma V(s') - V(s)A(s,a)=r+γV(s′)−V(s)r^i=ri−rˉgroup\hat{r}_i = r_i - \bar{r}_{\text{group}}r^i​=ri​−rˉgroup​
    显存占用高 (3个模型)较低 (2个模型)
    训练稳定性对价值模型质量敏感更稳定 (组基线)
    实现复杂度高低

    KL 散度：安全制动器

    KL 散度惩罚 −β⋅DKL(πθ∣∣πref)-\beta \cdot D_{KL}(\pi_\theta || \pi_{\text{ref}})−β⋅DKL​(πθ​∣∣πref​) 防止策略偏离 SFT 基线过远，否则会导致格式和推理模式的灾难性遗忘。系数 β\betaβ 直接控制探索与利用的权衡：当 β=0.01\beta=0.01β=0.01 时，策略可能会产生退化输出；当 β=0.5\beta=0.5β=0.5 时，学习实际上会停滞；推荐范围 0.05-0.1 可以在发现与稳定性之间取得平衡。

    在 GRPO 训练期间，请与平均奖励一起监控 KL 散度指标。如果 KL 散度迅速上升而奖励停滞或下降，说明策略正在偏离参考策略——请增加 kl_coef。如果 KL 散度保持接近零且奖励没有改善，说明策略过于保守——请降低 kl_coef 或提高 temperature。
