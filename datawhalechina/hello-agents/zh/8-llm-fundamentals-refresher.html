    LLM 基础回顾

    24 分钟等级: 进阶

    本页重点回顾大语言模型（LLM）的基础知识——驱动现代 AI Agent 的认知引擎。本指南并非详尽的教科书式论述，而是提炼了中级开发者需要理解的核心概念：LLM 为何有效、如何处理语言，及其固有局限性对 Agent 设计意味着什么。我们将追溯从统计语言模型到 Transformer 革命的演进轨迹，剖析分词与提示词工程的机制，并直面塑造每个 Agent 架构决策的缩放定律与幻觉挑战。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    从统计模型到神经语言模型

    语言模型的故事始于一个看似简单的问题：如何计算一个句子的概率？ **语言模型（LM）**通过对词序列的概率进行建模来回答这个问题。概率的链式法则给出了理论上的理想形式——P(w1,w2,…,wm)=P(w1)⋅P(w2∣w1)⋅P(w3∣w1,w2)⋯P(wm∣w1,…,wm−1)P(w_1, w_2, \dots, w_m) = P(w_1) \cdot P(w_2|w_1) \cdot P(w_3|w_1,w_2) \cdots P(w_m|w_1,\dots,w_{m-1})P(w1​,w2​,…,wm​)=P(w1​)⋅P(w2​∣w1​)⋅P(w3​∣w1​,w2​)⋯P(wm​∣w1​,…,wm−1​)——但直接估计这些条件概率在长序列中是不可行的，因为大多数词组合从未出现在任何有限的语料库中。

    N-gram 模型通过马尔可夫假设解决了这个问题：一个词的概率仅取决于前 n−1n-1n−1 个词。对于 Bigram 模型（N=2），这简化为 P(wi∣w1,…,wi−1)≈P(wi∣wi−1)P(w_i|w_1,\dots,w_{i-1}) \approx P(w_i|w_{i-1})P(wi​∣w1​,…,wi−1​)≈P(wi​∣wi−1​)，通过最大似然估计计算为 P(wi∣wi−1)=Count(wi−1,wi)Count(wi−1)P(w_i|w_{i-1}) = \frac{\text{Count}(w_{i-1}, w_i)}{\text{Count}(w_{i-1})}P(wi​∣wi−1​)=Count(wi−1​)Count(wi−1​,wi​)​。尽管 N-gram 模型简洁且计算高效，但存在两个致命缺陷：数据稀疏（未出现的序列概率为零）和泛化能力差（模型将“agent learns”和“robot learns”视为完全无关，无法传递语义相似性）。

    神经网络语言模型通过引入词嵌入克服了这些限制——这是一种连续的向量表示，语义相似的词在高维空间中聚集。神经网络不再进行离散的符号计数，而是学习从上下文词向量到下一个词的概率分布的映射。这种嵌入空间捕获了丰富的关联结构：经典的演示 vector("King") - vector("Man") + vector("Woman") ≈ vector("Queen") 揭示了模型纯粹从数据中内化了类比关系。然而，早期的前馈神经语言模型仍然存在固定上下文窗口的限制——它们只能看到前 n−1n-1n−1 个词，与 N-gram 模型如出一辙。

    循环神经网络（RNN）通过引入充当短期记忆的隐藏状态，打破了固定窗口的约束，沿着序列传递信息。然而，标准 RNN 存在长距离依赖问题：梯度在多个时间步反向传播时会消失或爆炸。**长短期记忆网络（LSTM）**通过复杂的门控机制——遗忘门、输入门和输出门——解决了这个问题，该机制通过专用的细胞状态控制信息流。尽管 LSTM 显著改善了序列建模，但其顺序计算的本质仍然是根本性的瓶颈：你必须处理完 token ttt，才能处理 token t+1t+1t+1。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    Transformer 架构

    在具有里程碑意义的论文《Attention Is All You Need》中提出的 Transformer，完全消除了循环计算，取而代之的是完全基于注意力机制的架构，从而实现了整个序列的并行处理。对于 Agent 开发者来说，理解 Transformer 是不可妥协的——驱动你的 Agent 的每一个 LLM 都建立在这一基础之上。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    编码器-解码器结构与核心模块

    最初的 Transformer 遵循为机器翻译设计的编码器-解码器架构。编码器读取并理解整个输入序列，为每个 token 生成富含上下文的向量表示。解码器随后以自回归方式生成输出序列，同时参考其自身先前的输出和编码器的表示。这种先理解，后生成的分工通过堆叠层实现，每层包含两个关键子模块：

    模块作用核心机制
    多头自注意力动态聚合整个序列的信息拆分到多个“头”的 Q-K-V 点积，提供多样化的关系视角
    位置前馈网络独立提取和转换每个 token 内的特征带有 ReLU 激活函数的两次线性变换：FFN(x)=max⁡(0,xW1+b1)W2+b2\text{FFN}(x) = \max(0, xW_1 + b_1)W_2 + b_2FFN(x)=max(0,xW1​+b1​)W2​+b2​

    每个子模块都包裹着残差连接（通过让信号绕过层来解决梯度消失）和层归一化（通过归一化特征分布来稳定训练）。由于自注意力是排列不变的——它没有内在的顺序感——位置编码通过正弦函数注入序列位置信息：PE(pos,2i)=sin⁡(pos/100002i/dmodel)PE_{(pos,2i)} = \sin(pos / 10000^{2i/d_{\text{model}}})PE(pos,2i)​=sin(pos/100002i/dmodel​) 和 PE(pos,2i+1)=cos⁡(pos/100002i/dmodel)PE_{(pos,2i+1)} = \cos(pos / 10000^{2i/d_{\text{model}}})PE(pos,2i+1)​=cos(pos/100002i/dmodel​)。这些确定性的位置向量在进入第一层之前，直接加到 token 嵌入上。

    纯解码器架构与自回归生成

    当 OpenAI 开发 GPT 时，他们认识到大多数语言任务——回答问题、写故事、生成代码——本质上都是下一 token 预测问题。你不需要一个单独的编码器在生成之前“理解”输入；你可以将整个输入视为生成的前缀。这一洞见促成了纯解码器架构，它完全舍弃了编码器，仅保留解码器堆栈。

    纯解码器模型以自回归方式工作：给定文本前缀，预测下一个最可能的 token，将其追加到前缀中，然后重复。为了防止模型在训练期间“偷看”未来的 token，掩码自注意力在 Softmax 归一化之前，将当前位置之后所有位置的注意力分数置零。这种因果掩码确保了位置 ttt 的预测仅依赖于位置 111 到 ttt。

    纯解码器架构的主导地位源于三大汇聚优势：(1) 统一的训练目标——在海量无标注文本上进行下一 token 预测，其扩展轻而易举；(2) 结构简单——更少的组件意味着更容易扩展到数千亿参数；(3) 天然适合生成——自回归循环完美契合了对话式和 Agent 工作流，模型必须逐个 token 地生成响应。当今每一个主流 LLM——GPT-4、Llama、Qwen、Claude——都采用了这一架构。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    与 LLM 交互：提示词工程与分词

    理解如何有效地与 LLM 沟通是一项直接影响 Agent 性能的实用技能。本节涵盖两个互补的维度：提示词的策略性设计，以及文本如何成为模型输入的机制性现实。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    采样参数：控制随机性与创造力的旋钮

    当 LLM 预测下一个 token 时，它会在其整个词汇表上产生一个概率分布。采样参数在选择之前重塑该分布，允许开发者在确定性与创造力之间取得平衡。

    参数机制效果典型 Agent 用例
    温度 (TTT)将 Softmax 重写为 pi(T)=ezi/T∑ezj/Tp_i^{(T)} = \frac{e^{z_i/T}}{\sum e^{z_j/T}}pi(T)​=∑ezj​/Tezi​/T​低温 → 更尖锐、更具确定性；高温 → 更平坦、更多样低温（0–0.3）用于代码/事实；高温（0.7–2.0）用于创意头脑风暴
    Top-k仅保留概率最高的 k 个 token，重新归一化将候选池限制在前 k 个，防止出现不太可能的 tokenk=40–50 用于平衡生成
    Top-p（核采样）保留累积概率 ≥ p 的最小 token 集合动态适应分布形状；兼顾尖锐和平坦分布p=0.9 用于通用生成

    当同时设置这三个参数时，它们按顺序应用：温度调整 → Top-k 过滤 → Top-p 过滤。边缘情况：温度=0 使 Top-k/Top-p 失去意义（始终选择概率最高的 token）；Top-k=1 使温度和 Top-p 失去意义（仅剩一个候选）。

    对于涉及工具使用和结构化推理的 Agent 工作流，倾向于使用低温（0–0.2）和受限的 Top-p（0.7–0.9）。高温下的创造发散可能导致模型偏离工具调用格式，从而破坏 Agent 的交互循环。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    提示词策略：从零样本到思维链

    你为 LLM 构建任务框架的方式极大地影响输出质量。提示词策略构成了从最少指导到结构化推理的渐进过程：

    零样本提示词完全依赖模型的预训练知识——你提供指令而不给示例。这对简单任务有效，但在细微或格式敏感的请求上可能会失败。单样本提示词添加了一个输入输出示例，展示了所需的格式和风格。少样本提示词提供了覆盖不同边缘情况的多个示例，让模型更丰富地理解任务边界。指令微调的影响不容小觑：现代聊天模型在指令-响应对上进行了微调，使其能够遵循直接的自然语言命令，而无需像早期文本补全模型那样依赖少样本的“示例教学”。

    思维链提示词是 Agent 推理领域最重要的进步。通过在提示词中加入“让我们一步步思考”，你迫使模型在得出最终答案之前外化其中间推理步骤。这将单次预测——在多步骤问题上经常失败——转变为深思熟虑且可验证的推理轨迹。CoT 非常有效，以至于它在大模型中的涌现成为了缩放定律研究的关键发现之一。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    分词：文本与模型之间的隐藏层

    在任何提示词到达 Transformer 之前，它必须被分词——从字符串转换为模型可处理的整数 ID 序列。分词算法的选择具有深远的实际影响，每个 Agent 开发者都必须铭记于心。

    早期的方法——基于词和基于字符的分词——都有致命缺陷。基于词的方法面临词汇量爆炸和未登录词（OOV）问题：任何未见过的词都无法表示。基于字符的方法消除了 OOV，但产生了语义无意义的单元和极长的序列。子词分词算法达到了最佳平衡，保持常见词完整的同时，将罕见词分解为有意义的片段。

    **字节对编码（BPE）**是 GPT 系列模型使用的算法，通过贪婪合并过程构建词汇表：从单个字符开始，迭代地将最频繁的相邻对合并为新 token，重复直到词汇表达到目标大小。变体包括 WordPiece（BERT 使用，基于似然提升而非频率进行合并）和 SentencePiece（Llama 使用，将空格视为常规字符，实现与语言无关的分词）。

    分词直接影响三个关键的 Agent 指标：(1) 上下文窗口消耗——相同的文本在不同语言和分词器下可能消耗截然不同的 token 数量；(2) API 成本——大多数提供商按 token 而非字符收费；(3) 模型行为异常——2+2 和 2 + 2 的分词结果可能不同，导致在看似相同的输入上表现不一致。请始终针对你的特定语言和领域测试分词行为。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    实践中调用开源 LLM

    对于需要数据隐私、离线操作或成本控制的场景，在本地部署开源模型至关重要。Hugging Face 的 transformers 库提供了标准化接口。其工作流程遵循清晰的管道：

    关键代码模式包括：(1) 从模型 ID 加载 AutoModelForCausalLM 和 AutoTokenizer；(2) 通过 tokenizer.apply_chat_template() 使用模型的聊天模板格式化消息；(3) 使用 tokenizer() 将文本编码为 token ID；(4) 带采样参数调用 model.generate()；(5) 通过 tokenizer.batch_decode() 仅解码新生成的 token。这种模式——格式化 → 分词 → 生成 → 解码——是任何 LLM 驱动的 Agent 的基础交互循环。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    模型选择：导航 LLM 领域

    为你的 Agent 选择合适的模型需要平衡多个维度。没有单一模型能在所有方面都表现出色——最佳选择取决于你的具体约束和需求。

    维度闭源（API）开源（本地）
    性能上限通常最高（GPT-4, Claude, Gemini）快速提升中（Llama 4, Qwen, Mistral）
    成本模型按 token 付费；小规模下可预测硬件+运维；大规模下摊销
    延迟取决于 API 和网络；因层级而异由你的硬件控制；量化可辅助降低
    上下文窗口高达 1M+ token（Gemini）通常 8K–128K；持续增长
    数据隐私数据离开你的基础设施数据保留在本地
    可定制性仅限于提示词工程可进行完全微调和合并
    生态系统成熟的 API，官方工具Hugging Face, vLLM, Ollama 社区

    对于处理敏感数据的企业 Agent，本地部署的开源模型提供了闭源 API 无法比拟的隐私保证。对于需要快速原型设计或最高推理能力的任务，闭源 API 仍是务实之选。最复杂的 Agent 架构往往结合两者：闭源模型用于高风险推理，开源模型用于大容量、隐私敏感的操作。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    缩放定律与 LLM 的局限性

    理解 LLM 为什么有效以及为什么失败，对于构建可靠的 Agent 至关重要。缩放定律解释了前者；幻觉解释了后者。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    缩放定律：幂律引擎

    缩放定律揭示了模型性能（以交叉熵损失衡量）与三个因素遵循可预测的幂律关系：参数量、训练数据量和计算预算。在双对数空间中，这些关系异常平滑——这意味着在训练开始之前，性能提升就可以被可靠地预测。

    DeepMind 的 Chinchilla 定律（2022）完善了这一理解，表明在固定的计算预算下，参数量和数据量之间存在一个最优比例。许多早期的大型模型是“过度参数化”的——它们本可以用更少的参数和更多的训练数据达到相同的性能。这一洞见重塑了该领域进行模型设计的方式。

    缩放最引人注目的后果也许是能力涌现：当模型规模跨过特定阈值时，会出现在较小模型中不存在或微不足道的全新能力。思维链推理、上下文学习和复杂的多步规划都在大规模下涌现——这些能力与 Agent 设计直接相关。这就是为什么 LLM 的规模对 Agent 任务如此重要，而单纯的基准分数并不能完全捕捉这一点。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    模型幻觉：可靠性挑战

    模型幻觉——生成与事实、用户输入或源文本相矛盾的内容——仍然是 Agent 可靠性最关键的局限。幻觉有三种形式：事实性（与现实事实矛盾）、忠实度（在摘要/翻译中未能反映源文本）和内在性（与模型自身的输入矛盾）。其根本原因交织在一起：嘈杂的训练数据、缺乏内置事实验证的自回归生成机制，以及统计模式匹配与真正理解之间的根本鸿沟。

    缓解策略在多个层面运作：

    层面策略机制Agent 集成
    数据高质量数据策展，RLHF减少来源中的错误模式选择经过强 RLHF 训练的模型
    模型不确定性表达，架构创新模型在不确定时发出信号在 Agent 循环中监控置信度分数
    推理RAG（检索增强生成）将生成锚定在检索到的外部事实上Agent 最常见的生产方案
    推理多步推理 + 验证在每个推理步骤进行自我检查天然契合 ReAct Agent 模式
    推理外部工具调用将事实查询卸载到权威来源工具使用 Agent 的核心模式

    这些策略的汇聚——特别是 RAG 结合工具增强推理——构成了当今大多数生产级 Agent 系统的架构骨干。幻觉无法被消除，但设计良好的 Agent 架构可以将其遏制并缓解至可接受的水平。

    来源：Chapter3-Fundamentals-of-Large-Language-Models.md

    核心要点与下一步

    本回顾涵盖了支撑 Agent 开发的重要 LLM 基础：

    • 模型演进——从 N-gram 的统计计数，到 RNN/LSTM 的序列记忆，再到 Transformer 的并行注意力——每一步都解决了其前身的根本局限，最终造就了驱动所有现代 LLM 的纯解码器自回归架构。
    • 交互机制——采样参数控制着创造力与确定性的权衡；从零样本到思维链的提示词策略塑造了推理行为；分词是影响成本、上下文甚至模型准确性的隐藏基础设施。
    • 实际选择——闭源与开源的决策，平衡了性能上限与数据隐私、可定制性及长期成本。
    • 根本局限——缩放定律解释了为什么更大的模型能获得涌现能力；幻觉解释了为什么必须将 Agent 设计为具备验证和基础锚定机制。

    有了这些基础，下一步是了解 LLM 如何嵌入到 Agent 循环中——即感知-思考-行动的周期，它将语言模型从文本生成器转变为自主的问题解决者。ReAct 模式实现 页面演示了思维链推理如何成为 Agent 决策循环的“思考”阶段，而记忆系统（工作、情景、语义） 和RAG 管道与检索 则展示了如何针对此处讨论的幻觉挑战锚定 Agent 输出。
