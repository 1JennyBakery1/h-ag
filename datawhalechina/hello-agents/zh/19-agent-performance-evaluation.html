    Agent 性能评估

    24 分钟等级: 进阶

    你如何知道你的 Agent 真正起效了？这不是指那种“看起来回答正确”的粗略感觉，而是指以严谨、可复现、经过基准验证的方式，将生产级系统与原型区分开来。本页将深入结构化地探讨评估 Agent 性能的理论、基准测试与实操工具——涵盖工具调用准确率（BFCL）、通用推理能力（GAIA）以及数据生成质量评估（LLM Judge / Win Rate）。

    为何 Agent 评估不可或缺

    设想一个配备了搜索工具的 SimpleAgent。它运行着，并给出响应——但当你更换 LLM 后端或微调系统提示词时，如何得知性能是提升了还是倒退了？没有系统化的评估，你如同盲人摸象。Agent 评估提供了标准化度量层，从而实现量化对比、弱点检测与可靠性保证。

    与传统软件测试中断言非黑即白不同，Agent 评估面临三大结构性挑战：输出不确定性（同一输入存在多个有效答案）、评估标准多样性（工具调用需要签名校验，推理任务需要步骤验证，生成任务需要质量打分）以及环境依赖性（搜索结果会变，API 会演进）。标准化的基准测试通过提供统一的数据集、指标与评分方法来应对这些挑战，使得跨系统比较具有实际意义。

    来源: Chapter12-Agent-Performance-Evaluation.md, [第十二章 智能体性能评估.md](docs/chapter12/第十二章 智能体性能评估.md#L1-L52)

    HelloAgents 评估系统架构

    HelloAgents 评估系统围绕三个评估场景进行设计，这三个场景因其学习曲线与实用价值而被选中：用于工具调用的 BFCL、用于通用推理的 GAIA，以及用于 LLM-as-evaluator 模式的 数据生成质量。该架构采用分层设计，每个基准测试都有专属的数据集加载器（Dataset loader）、评估器引擎（Evaluator engine）和指标计算器（Metrics calculator），它们全部统一封装在 Tool 包装器下，以实现无缝的 Agent 集成。

    BFCL：工具调用能力评估

    基准测试结构与 AST 匹配

    BFCL（Berkeley Function Calling Leaderboard）评估 Agent 的核心能力：理解自然语言意图、选择正确工具并构建正确的函数调用。该基准测试包含四个难度递增的类别：

    类别描述示例场景
    Simple从小规模工具集中进行单次函数调用"北京的天气如何？" → get_weather(location="Beijing")
    Multiple从更大规模的工具集中选择并调用一个函数多个候选工具，选择正确的一个
    Parallel同时调用多个函数"获取北京和上海的天气" → 两个并行调用
    Irrelevance判断是否不需要函数调用常识问题 → 无需工具调用

    核心评估算法是 AST 匹配（抽象语法树匹配）——而非字符串比较，而是结构等价性。给定预测调用 PPP 和真实标签 GGG：

    AST_Match(P,G)={1if AST(P)≡AST(G)0otherwise\text{AST\_Match}(P, G) = \begin{cases} 1 & \text{if } \text{AST}(P) \equiv \text{AST}(G) \\ 0 & \text{otherwise} \end{cases}AST_Match(P,G)={10​if AST(P)≡AST(G)otherwise​

    当满足以下条件时，两棵语法树等价：(1) 函数名完全匹配，(2) 参数键值集无论顺序均相等，(3) 每个参数值在语义上等价（例如，2+3 ≡ 5）。这使得 AST 匹配在抵抗格式差异的同时，依然对语义正确性保持严格要求。

    来源: Chapter12-Agent-Performance-Evaluation.md

    渐进式评估与优化策略

    GAIA：通用 AI 助手能力评估

    基准测试设计理念

    GAIA（General AI Assistants）——由 Meta AI 和 Hugging Face 联合创建——评估使 Agent 在真实场景中真正发挥作用的综合推理能力。BFCL 孤立地测试工具调用，而 GAIA 则测试 Agent 能否组合多种能力：多步推理、知识应用、多模态理解、网页浏览与文件操作。

    该数据集包含 466 个精心设计的问题，分布在三个难度级别：

    级别推理步骤典型所需能力示例
    Level 10–1 步单次查找，简单事实"法国的首都是哪里？"
    Level 22–4 步多步推理，工具链式调用"加州人口前三大城市的总人口"
    Level 35+ 步复杂规划，文件处理，网络调研需要文档分析 + 网络搜索 + 计算的任务

    每个样本包含标注者元数据，详细说明了预期的推理步骤、所需工具与预估时间——这提供了超越简单通过/失败的丰富诊断信息。

    来源: Chapter12-Agent-Performance-Evaluation.md

    准精确匹配算法

    GAIA 使用 准精确匹配（Quasi Exact Match）——一种先标准化再比较的算法，避免因表面格式差异而扣分。给定预测答案 ApredA_{\text{pred}}Apred​ 和真实答案 AtrueA_{\text{true}}Atrue​：

    Quasi_Exact_Match(Apred,Atrue)={1if N(Apred)=N(Atrue)0otherwise\text{Quasi\_Exact\_Match}(A_{\text{pred}}, A_{\text{true}}) = \begin{cases} 1 & \text{if } \mathcal{N}(A_{\text{pred}}) = \mathcal{N}(A_{\text{true}}) \\ 0 & \text{otherwise} \end{cases}Quasi_Exact_Match(Apred​,Atrue​)={10​if N(Apred​)=N(Atrue​)otherwise​

    标准化函数 N(⋅)\mathcal{N}(\cdot)N(⋅) 应用特定类型规则：

    答案类型标准化规则示例
    数值移除逗号、单位（$, %）"$1,234.56" → "1234.56"
    字符串小写化、去除冠词、移除标点"The United States of America" → "united states of america"
    列表按字母排序、标准化每个元素"Paris, London, Berlin" → "berlin, london, paris"

    GAIA 指标与难度分析

    GAIA 定义了四项指标，共同提供全面的能力画像：

    1. 精确匹配率（Exact Match Rate） ——核心指标：

    Exact Match Rate=1N∑i=1NQuasi_Exact_Match(Apred,i,Atrue,i)\text{Exact Match Rate} = \frac{1}{N} \sum_{i=1}^{N} \text{Quasi\_Exact\_Match}(A_{\text{pred},i}, A_{\text{true},i})Exact Match Rate=N1​∑i=1N​Quasi_Exact_Match(Apred,i​,Atrue,i​)

    2. 级别准确率（Level-wise Accuracy） ——各难度的表现：

    Accuracyℓ=1∣Dℓ∣∑i∈DℓQuasi_Exact_Match(Apred,i,Atrue,i)\text{Accuracy}_\ell = \frac{1}{|D_\ell|} \sum_{i \in D_\ell} \text{Quasi\_Exact\_Match}(A_{\text{pred},i}, A_{\text{true},i})Accuracyℓ​=∣Dℓ​∣1​∑i∈Dℓ​​Quasi_Exact_Match(Apred,i​,Atrue,i​)

    3. 难度递进下降率（Difficulty Progression Drop Rate） ——衡量复杂性下的能力衰退：

    Drop Rateℓ→ℓ+1=Accuracyℓ−Accuracyℓ+1Accuracyℓ\text{Drop Rate}_{\ell \to \ell+1} = \frac{\text{Accuracy}_\ell - \text{Accuracy}_{\ell+1}}{\text{Accuracy}_\ell}Drop Rateℓ→ℓ+1​=Accuracyℓ​Accuracyℓ​−Accuracyℓ+1​​

    4. 平均推理步骤（Average Reasoning Steps） ——正确解法的效率：

    Avg Steps=1Ncorrect∑i∈Correctstepsi\text{Avg Steps} = \frac{1}{N_{\text{correct}}} \sum_{i \in \text{Correct}} \text{steps}_iAvg Steps=Ncorrect​1​∑i∈Correct​stepsi​

    指标解读指南
    Exact Match Rate = 1.0所有样本均正确
    Drop Rate = 0.0难度未导致性能下降（理想状态）
    Drop Rate = 0.3难度增加时准确率损失 30%——已识别出能力边界
    Avg Steps 远超标注者预估Agent 推理效率低下

    数据生成质量评估

    完整的评估闭环

    第三个评估场景解决的是一个不同的问题：当 Agent 生成训练或测试数据（例如 AIME 风格的数学题）时，你如何评估生成数据本身的质量？此场景演示了使用 Agent 创建数据然后评估该数据的完整闭环——这一模式在 Agentic RL 流水线中正变得愈发重要。

    评估流水线结合了三种互补方法：

    LLM Judge 使用更强的 LLM（通常为 GPT-4）在多个维度上按 1–5 分制对生成数据进行评分：正确性、清晰度、难度匹配与完整性。Win Rate 将生成样本与参考数据（例如真实的 AIME 题目）配对，统计生成数据被判定为更优的频率。人工验证提供最终的真实情况校验。

    来源: Chapter12-Agent-Performance-Evaluation.md, README.md
