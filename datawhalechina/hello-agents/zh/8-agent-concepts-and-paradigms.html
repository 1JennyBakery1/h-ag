    Agent 概念与范式

    26 分钟等级: 入门

    究竟什么才是 Agent —— 为什么这个概念会成为现代 AI 工程的引力中心？本页将从第一性原理出发，为你提供关于 Agent 的基础认知：它的定义，它在三个互补维度上的分类，大语言模型带来的范式转变，以及让每个 Agent 运转起来的核心运作机制。无论你是初次构建 Agent，还是想要将已有的直觉体系化，这里都是构建概念框架的起点。

    什么是 Agent？

    在人工智能领域，Agent 被定义为能够通过传感器感知其环境，并自主地通过执行器采取行动以实现特定目标的任何实体。这一定义源于 Russell 和 Norvig 的经典框架，包含四个不可分割的要素：

    要素作用示例（自动驾驶汽车）示例（交易算法）
    环境Agent 运行的外部世界动态道路交通实时金融市场
    传感器从环境接收信息摄像头、激光雷达、GPS市场数据流、订单簿
    执行器对环境施加作用以改变其状态转向、刹车、油门订单执行 API
    自主性基于感知与内部状态的独立决策选择变道决定买入/卖出时机

    关键的区分因素在于自主性。一个死板执行 if price < threshold then buy 的脚本不是 Agent —— 它缺乏独立判断。Agent 会根据内部状态评估其感知，并决定该做什么，而不是仅仅遵循预设的路径。这种从感知到行动的闭环，是每个 Agent 系统的心跳。

    来源：第一章 初识智能体.md, Chapter1-Introduction-to-Agents.md

    进化阶梯：传统 Agent 范式

    在 LLM 时代之前，AI 研究者花了几十年的时间，打磨出了一条清晰的 Agent 架构进化路径。每一步都解决了其前身的特定局限性，理解这一脉络对于掌握为什么 LLM Agent 代表着范式转变而非渐进式改良至关重要。

    简单反射 Agent 基于硬编码的条件-行动规则运行 —— 比如温度降至阈值以下时开启加热的恒温器。它们快速且可靠，但完全缺乏上下文感知。当仅凭当前感知不足以做出良好决策时，我们需要更强大的东西。

    基于模型的反射 Agent 维护着一个内部世界模型，用于追踪当前无法直接感知的环境方面。例如，自动驾驶汽车会记住曾有行人处于立柱后方，即使行人被短暂遮挡。这种内部状态丰富了决策过程，但在根本上仍是反应式的。

    基于目标的 Agent 引入了一个根本性转变：从反应到规划。它们显式地表示期望的目标状态，并在可能的行动序列中搜索以找到通往目标的路径。选择去办公室路线的导航系统就是典型 —— 它不仅对道路做出反应，还规划到达目的地的路径。

    基于效用的 Agent 认识到现实世界的目标很少是单一的。你希望到达办公室，但也希望尽量减少时间、燃料成本和交通拥堵。效用函数为每个可能的世界状态分配一个数值分数，使 Agent 能够在相互竞争的目标之间进行优化，而非仅仅满足一个目标。

    学习型 Agent 闭合了这条进化链。它们不再完全依赖人类设计的规则或效用函数，而是引入了一个学习元素，根据经验来修改性能元素。强化学习 —— Agent 通过自我对弈和奖励信号发现制胜策略 —— 是其典型的实现方式。AlphaGo Zero 无需人类演示数据即精通围棋，便是这一范式的里程碑成就。

    来源：第一章 初识智能体.md, Chapter1-Introduction-to-Agents.md

    LLM 革命：新范式

    GPT 级别大语言模型的出现，并非仅仅在进化阶梯上增加了一级 —— 它从根本上改变了 Agent 系统的架构。核心决策引擎从人工设计的逻辑转变为在海量语料库上训练的神经网络，带来了深远的影响：

    维度传统 AgentLLM 驱动的 Agent
    核心引擎手工编写的规则 / 搜索算法预训练的神经网络 (LLM)
    知识来源由工程师显式编程从训练数据中隐式学习
    交互模式结构化、正式的接口自然语言、开放式的
    适应性局限于编程预设的突发情况通过推理泛化至未见任务
    工具使用固定顺序的预定义 API 调用根据上下文动态选择和调用工具
    错误处理遇到意外输入则失败能够即兴发挥、重新规划和自我纠正

    考虑一个智能旅行助手。在 LLM Agent 出现之前，用户必须在天气应用、地图服务和预订平台之间手动协调 —— 人类充当了整合者。LLM Agent 将此工作流压缩为单次交互：它将“规划一次去厦门的旅行”分解为子任务（[确认偏好] → [查询目的地信息] → [草拟行程] → [预订机票]），识别信息缺口并主动调用外部工具来填补，并将用户反馈（“那家酒店超出我的预算了”）视为新约束，以动态调整其计划。没有硬编码的 if-then 链来控制这个过程 —— LLM 是通过推理来推进的。

    根本性转变：我们正从开发专用自动化工具转向构建能够自主解决问题的系统。核心工程任务不再是编写过程式代码，而是引导通用推理引擎去规划、行动和学习。

    来源：第一章 初识智能体.md, Chapter1-Introduction-to-Agents.md

    Agent 分类的三个维度

    单一的分类视角无法涵盖 Agent 架构的全部丰富性。三个互补的维度 —— 每个都阐明了不同的设计权衡 —— 提供了一幅更完整的图景。

    维度一：内部决策架构

    这就是上述的进化阶梯：简单反射 → 基于模型 → 基于目标 → 基于效用 → 学习型。它根据内部决策机制的复杂性对 Agent 进行分类，从受规则约束的反应式进化到自主的自我改进。

    维度二：时间与反应性

    此维度捕捉了速度与深思熟虑之间的权衡 —— Agent 是在感知后立即行动，还是在行动前投入时间进行规划。

    类型决策延迟规划深度优势劣势示例
    反应式近乎零无/极少速度快；计算量低无长期策略安全气囊部署；高频交易机器人
    深思式高深度搜索处理复杂、长周期任务速度慢；计算量大国际象棋 AI；商业计划生成器
    混合式可变分层平衡速度与前瞻性架构复杂旅行助手；现代 LLM Agent

    现代 LLM Agent 通过“推理-行动-观察”微循环体现了混合模式：推理阶段是深思式的（规划下一步），而行动与观察阶段是反应式的（执行并立即处理反馈）。通过将宏大任务分解为许多这样的微循环，Agent 同时保持了响应性和连贯性。

    维度三：知识表示

    这是最深层的维度，触及了 AI 核心长达半个世纪的争论：Agent 的知识以何种形式存在？

    符号主义 AI（“图书管理员”）将知识存储为显式的、人类可读的规则 —— 透明且可审计，但当现实不符合规则时则显得脆弱。亚符号主义 AI（“通过观察学习的孩童”）将知识编码为分布在上千亿参数中的统计模式 —— 强大且灵活，但不透明。神经符号主义 AI 旨在统一两者，映射了卡尼曼的双过程理论：系统 1（快速、直觉、模式驱动）用于感知和语言生成，系统 2（缓慢、逻辑、规则驱动）用于结构化推理和验证。

    LLM Agent 是神经符号主义 AI 的典型实现：其神经网络核心提供了系统 1 能力（语言流畅性、模式识别），而结构化提示词和工具使用协议则在上面叠加了系统 2 推理（逐步推演、API 调用构建）。

    来源：第一章 初识智能体.md, Chapter1-Introduction-to-Agents.md

    Agent 循环：Agent 如何运作

    理解 Agent 是什么，需要理解 Agent 做什么。核心运作机制是 Agent 循环 —— 一个感知、推理和行动的持续循环，直到任务完成。

    PEAS 模型：定义任务环境

    在 Agent 行动之前，必须使用 PEAS 模型精确刻画其任务环境：Performance measure（性能度量）、Environment（环境）、Actuators（执行器）和 Sensors（传感器）。以旅行助手为例：

    PEAS 组件旅行助手规范
    Performance（性能）用户满意度；行程完整性；成本效益
    Environment（环境）机票/酒店预订 API；天气服务；用户聊天界面
    Actuators（执行器）API 调用（搜索、预订）；自然语言响应
    Sensors（传感器）用户文本输入；API 响应数据；通知监听器

    LLM Agent 通常运行在部分可观察（API 仅返回可用数据的切片）、随机性（查询间机票价格波动）、多 Agent（其他用户和机器人争夺相同资源）以及序列化与动态（当前行动影响未来状态，且环境在深思熟虑期间发生变化）的环境中。

    思考-行动-观察协议

    在工程实践中，Agent 循环通过结构化的交互协议具体化。每个 Agent 输出遵循严格的格式：

    • Thought（思考）：Agent 内部推理的自然语言“快照” —— 它如何分析当前情况、分解问题并规划下一步。
    • Action（行动）：要执行的具体操作，通常表示为带参数的函数调用。
    • Observation（观察）：环境的响应，由传感器层处理为简明的自然语言。
    Thought: 用户想知道北京的天气。我需要调用天气工具。
Action: get_weather(city="Beijing")

Observation: 北京目前晴朗，26°C，微风。

    外部的解析器拦截 Action 字段，调用相应的函数，并将结果作为 Observation 反馈回去。此循环持续进行，直到 Agent 发出 Finish[最终答案] 动作。该协议的优雅之处在于，它使 Agent 的推理变得可读 —— 你可以检查每一步 Thought，以理解 Agent 为什么选择特定的行动。

    思考-行动-观察协议是几乎所有现代 Agent 框架（LangChain、LlamaIndex 等）的骨架。在调试 Agent 时，务必首先检查 Thought 追踪 —— 大多数故障源于推理缺陷，而非工具调用损坏。

    来源：第一章 初识智能体.md, Chapter1-Introduction-to-Agents.md

    构建你的第一个 Agent：实战演练

    理论在实践中结晶。本仓库包含一个完整且极简的 Agent 实现，用约 200 行 Python 代码演示了上述所有概念。让我们剖析其架构。

    系统组件

    FirstAgentTest.py 中的实现由四个紧密集成的组件构成：

    1. 系统提示词 —— 这是 Agent 的“操作手册”。它告知 LLM 扮演什么角色、有哪些可用工具，最关键的是，如何格式化其输出。提示词强制执行严格的 Thought: ... Action: ... 模式，包含两种合法的行动形式：工具调用（function_name(arg="value")）和任务完成（Finish[answer]）。

    2. 工具函数 —— 每个工具将外部 API 调用封装在整洁的 Python 函数签名背后。get_weather 查询免费的 wttr.in 服务；get_attraction 使用 Tavily Search API。两者都返回自然语言字符串，这点至关重要 —— LLM 处理文本，而非原始 JSON。这些工具注册在 available_tools 字典中，供运行时调度。

    3. LLM 客户端 —— OpenAICompatibleClient 封装了 OpenAI API，接受 model、api_key 和 base_url 参数。这种设计支持任何兼容 OpenAI 的端点（Azure、Ollama、vLLM），使 Agent 可跨提供商移植。

    4. 主循环 —— 编排核心。它维护一个 prompt_history 列表，追加每次 LLM 的输出和观察结果，并使用正则表达式解析出 Thought 和 Action 字段。当检测到工具调用时，它会分发到相应的函数；当检测到 Finish[...] 时，它提取并返回最终答案。

    执行追踪

    任务：“查询北京今天的天气，然后根据天气推荐一个旅游景点。”

    循环Thought（思考）Action（行动）Observation（观察）
    1需要先获取北京的天气，然后根据天气推荐。get_weather(city="北京")北京：晴朗，26°C
    2天气晴朗温和 —— 现在我可以推荐景点了。get_attraction(city="北京", weather="Sunny")颐和园（湖光山色、古典建筑）；长城（壮丽景色、历史意义）
    3已有天气和景点信息 —— 可以回答了。Finish[北京今天 26°C 晴朗，非常适合户外活动。推荐颐和园...](任务完成)

    这三次循环追踪演示了 Agent 的四个核心能力：任务分解（先天气后景点）、工具调用（正确的 API 选择和参数化）、上下文理解（利用天气结果辅助景点查询），以及结果综合（将两次观察结合为连贯的最终答案）。

    最大循环次数（本例中为 5）并非随意设定 —— 它是关键的安全护栏。若没有它，陷入推理错误的 Agent 可能会无限循环，白白消耗 API 额度且产生无用输出。在生产级 Agent 中，务必设置 max_iterations 边界。

    来源：FirstAgentTest.py, 第一章 初识智能体.md

    Agent 协作模式：工具与协作者

    Agent 并非孤立存在 —— 它们以两种截然不同的模式与人类协作。

    模式一：Agent 作为开发者工具

    在这种模式下，Agent 作为增强工具深度融入开发者的工作流。它自动化繁琐、重复的任务，而开发者保留创造性和架构控制权。该领域的关键产品各具特色：

    工具集成方式核心优势
    GitHub Copilot编辑器插件（VS Code 等）实时代码自动补全；深度编辑器集成
    Claude Code基于终端的助手理解完整代码库；执行编辑、测试和调试
    CursorAI 原生代码编辑器将 AI 交互作为一等设计原则；而非生硬拼凑
    Trae轻量级独立工具快速代码生成和自动化重构

    共性在于：AI 深度融入软件开发生命周期，通过高效的人机协作工作流重塑工程生产力。

    模式二：Agent 作为自主协作者

    在这里，人类委派的是高层目标，而非逐步指令。Agent 自主规划、执行和迭代 —— 充当真正的项目伙伴而非工具。三种架构模式占据主导：

    1. 单 Agent 自主循环 —— 一个通用 Agent 循环经历“思考 → 规划 → 执行 → 反思”以实现开放性目标（如 AgentGPT）。
    2. 多 Agent 协作 —— 多个专业化 Agent 模拟人类团队：角色扮演对话（CAMEL），结构化团队工作流（MetaGPT、CrewAI），或对话式编排（AutoGen）。
    3. 高级控制流 —— 诸如 LangGraph 之类的框架将执行建模为状态图，以工程严谨性实现循环、分支、回溯和人机交互检查点。

    工作流与 Agent：核心区别

    这是每位从业者都必须内化的概念边界：

    方面工作流Agent
    控制逻辑预定义的静态序列动态的、自我导向的
    决策制定人类编写的 if-then 规则实时的 LLM 推理
    适应性遇到意外输入则失败能够即兴发挥和重新规划
    透明度完全可预测的执行路径通过 Thought 追踪可见推理过程
    最适用于确定性、可重复的过程开放性、依赖上下文的任务

    工作流告诉 AI 逐步如何做。Agent 告诉 AI 要实现什么，并让它自己想出怎么做。

    以我们的旅行助手为例：工作流会硬编码 if weather == "sunny" then recommend("颐和园")，需要人类预判并编码所有可能性。而 Agent 则根据天气观察推理出建议 —— 如果下雨，它会自主转向室内景点，无需任何预先编写的规则。这种基于实时上下文的动态推理正是 Agent 的核心价值主张。

    来源：第一章 初识智能体.md, Chapter1-Introduction-to-Agents.md

    核心要点

    阅读完本页后，你应当建立清晰的思维模型：

    • Agent 的定义 —— 四要素（环境、传感器、执行器、自主性）以及为何自主性是区分关键。
    • 进化弧线 —— 从简单反射到学习型 Agent，每一步都解决了其前身的特定局限。
    • LLM 范式转变 —— 从手工逻辑到神经推理，以及为什么这是质变而非量变。
    • 三个分类视角 —— 决策架构（复杂性）、时间/反应性（速度与深思熟虑）、知识表示（符号与模式与混合）。
    • Agent 循环 —— 感知 → 思考 → 行动 → 观察的循环，以及用于刻画任务环境的 PEAS 模型。
    • 工作流 ≠ Agent —— 预定义执行与目标导向自主性的区别。
