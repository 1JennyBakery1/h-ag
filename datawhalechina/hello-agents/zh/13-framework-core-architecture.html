    框架核心架构

    19 分钟等级: 进阶

    HelloAgents 框架是一个从零构建的轻量级 Agent 框架，其设计遵循三大指导原则：分层解耦、单一职责和统一接口。与主流框架以牺牲简洁性换取通用性不同，HelloAgents 优先考虑教学友好性与渐进式学习——每一个核心功能你都能自行构建，每一种抽象你都能完全理解。本页展示了将所有后续框架组件（从 LLM 网关到工具注册中心）紧密联系在一起的架构蓝图。

    为什么要构建你自己的 Agent 框架

    在深入架构之前，有必要了解其设计动机。现有的市场框架虽然功能丰富，却引入了尤其阻碍学习者的摩擦：过度抽象将核心逻辑掩埋在数十个概念层（Chain、Agent、Tool、Memory、Retriever……）之下；快速迭代导致版本间的 API 发生破坏性变更；黑盒实现阻碍了深度定制；复杂的依赖树在生产环境中引发冲突。从零构建能将你从框架的使用者转变为构建者——你将深度理解 Agent 的思考过程、工具调用机制以及设计模式的权衡，同时保留对每一行代码的完全掌控。

    来源: Chapter7-Building-Your-Agent-Framework.md

    设计哲学

    HelloAgents 围绕一个核心问题展开：学习者如何既能快速上手，又能深入理解 Agent 的工作机制？ 答案体现在四大设计支柱中。轻量且教学友好：核心代码按章节分离，依赖数量降至最低，任何具备合理编程基础的开发者都应能在合理时间内完全理解该框架。基于标准 API 的务实选择：HelloAgents 构建在兼容 OpenAI 的 API 标准之上，而非发明新的抽象层，确保每个主流 LLM 提供商都无需适配代码即可接入。渐进式学习路径：每章代码均保存为可版本化且可通过 pip 安装的包，学习者可以先体验后实现，无需担心破坏性变更。统一的“Tool”抽象——一切皆 Tool：除了核心 Agent 类之外，所有可扩展模块（Memory、RAG、RL、MCP 协议）均作为 Tool 实现，从根本上简化了心智模型。

    来源: Chapter7-Building-Your-Agent-Framework.md

    HelloAgentsLLM — LLM 网关

    HelloAgentsLLM 是所有模型通信的统一入口。它同时解决了三个问题：多提供商切换（OpenAI、ModelScope、智谱 AI 等）、本地模型集成（VLLM、Ollama）以及零配置自动检测。其设计刻意保持可扩展性——你通过继承类并重写 __init__ 来添加新提供商，而非修改源码。

    核心接口

    Message 类

    Message 类标准化了所有组件间的通信。其 role 字段受 Literal["user", "assistant", "system", "tool"] 约束——直接映射到 OpenAI Chat Completion 规范——并且其 to_dict() 方法会生成 API 所期望的精确字典格式，消除了任何序列化猜测。

    metadata 字段被刻意设计为开放式——它承载工具调用轨迹、计时数据或下游组件所需的任何上下文，而不会污染 content 字段。

    Agent 范式实现

    前面章节中的所有四种经典范式都被重构为共享相同基类、消息系统和 LLM 网关的框架组件。下表总结了每种范式如何映射到框架：

    Agent核心循环工具支持关键提示词策略自定义入口
    SimpleAgent单次对话可选，通过 [TOOL_CALL:name:params] 格式角色 + 可选的工具描述注入run()、stream_run()、add_tool()
    ReActAgentThought → Action → Observation 循环必需，通过 ToolRegistry带有 tool_name[input] 的严格单步格式max_steps、custom_prompt
    ReflectionAgentGenerate → Reflect → Refine无（纯推理）泛化的三阶段提示词（initial/reflect/refine）custom_prompts 字典
    PlanAndSolveAgentPlan（列表） → 逐步 Execute无（委托给子 Agent）用于计划解析的结构化 Python 列表输出用于 planner/executor 的 custom_prompts
    FunctionCallAgent原生 OpenAI 函数调用必需，通过 JSON schemaOpenAI 原生工具 schema，无需提示词技巧_build_tool_schemas()、_invoke_with_tools()

    SimpleAgent — 对话基线

    SimpleAgent 展示了框架上的最小可行 Agent：它构建一个消息列表（系统提示词 → 历史记录 → 当前输入），调用 LLM，并将交互存储在历史记录中。当 enable_tool_calling=True 且提供了 ToolRegistry 时，它会从 LLM 的响应中解析 [TOOL_CALL:name:params] 标记，执行相应的工具，反馈结果，并循环直至达到 max_tool_iterations。此设计使工具调用路径可选且透明——同一个 run() 方法即可处理两种情况。

    来源: Chapter7-Building-Your-Agent-Framework.md

    ReActAgent — Reason-Act 循环

    基于框架的 ReActAgent 用一个集成了 ToolRegistry 的可配置循环取代了第 4 章的独立脚本。提示词模板强制执行严格的格式约束——每次响应仅允许一个步骤，动作必须是 tool_name[input] 或 Finish[answer]——这极大降低了解析失败率。max_steps 参数防止了无限循环。每次迭代都会将 Action 和 Observation 条目追加到 current_history，并在下一次提示词中重新注入，让 LLM 能完全洞察其先前的推理链。

    来源: Chapter7-Building-Your-Agent-Framework.md

    ReflectionAgent 与 PlanAndSolveAgent

    ReflectionAgent 将第 4 章特定于代码生成的提示词泛化为领域无关的三阶段流水线（initial → reflect → refine），使其适用于文本生成、分析以及任何可通过自我批评提升质量的任务。custom_prompts 字典允许你在无需子类化的情况下替换为领域特定的变体。

    PlanAndSolveAgent 要求 Planner 以 Python 列表格式（例如，["Step 1", "Step 2", ...]）输出计划，取代了第 4 章中的自由文本计划。这种结构化输出实现了确定性的解析和 Executor 阶段的健壮异常处理。每个步骤的结果会累积到一个 history 字符串中，Executor 会连同原始问题和完整计划一起接收该字符串，从而确保所有步骤的上下文连贯性。

    来源: Chapter7-Building-Your-Agent-Framework.md

    FunctionCallAgent — 原生函数调用

    在 hello-agents v0.2.8 中引入的 FunctionCallAgent 利用了 OpenAI 的原生函数调用机制，而非基于提示词的工具调用。它通过 _build_tool_schemas() 从工具描述构建 JSON schema，将其传递给 OpenAI API 的 tools 参数，并让模型决定何时以及如何调用函数。这种方法比正则解析 [TOOL_CALL:...] 标记要健壮得多，因为模型的输出在结构上受 API 契约保证，而不仅仅依赖于提示词工程。

    来源: Chapter7-Building-Your-Agent-Framework.md

    Tool 系统架构

    Tool 系统通过两种抽象实现了“一切皆 Tool”的哲学：Tool 基类（每个工具都必须实现）和 ToolRegistry（负责管理发现和执行）。

    Tool 基类

    run() 方法接受一个字典并返回一个字符串，使得每个工具的执行签名保持一致。get_parameters() 方法使 ToolRegistry 能够为 Agent 提示词或 OpenAI 函数 schema 自动生成工具描述，而 ToolParameter 类为每个参数提供了类型、描述以及必选/可选元数据。

    “一切皆 Tool”模式意味着 Memory、RAG 甚至 MCP 协议适配器都被注册为 Tool。这让任何 Agent 都能通过相同的 ToolRegistry.execute_tool() 调用来访问它们——无需特殊情况下的代码路径。当你后续添加 MemoryTool 或 RAGTool 时，Agent 无需任何架构变更即可获得这些能力。

    ToolRegistry

    ToolRegistry 充当中央查找表。它提供了 register_tool()、unregister()、execute_tool()、get_tools_description() 和 list_tools()——一个精简但完备的 API，供所有 Agent 统一调用。get_tools_description() 方法尤为重要：它生成被注入到 Agent 提示词中的自然语言工具列表，同时也为 FunctionCallAgent 驱动 JSON schema 的生成。

    来源: Chapter7-Building-Your-Agent-Framework.md
