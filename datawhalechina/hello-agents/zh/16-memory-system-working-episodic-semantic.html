    记忆系统（工作记忆、情景记忆、语义记忆）

    23 分钟等级: 进阶

    一个没有记忆的 Agent 就像一条金鱼——当下聪明，却无法从过去中学习或随着时间的推移进行适应。本页将深入探讨 HelloAgents 记忆系统，这是一个受认知科学启发的四层架构，赋予 Agent 编码、存储、检索、整合以及主动遗忘信息的能力——映射了人类大脑如何跨工作记忆、情景记忆、语义记忆和感知记忆寄存器来管理记忆。阅读完本文后，你不仅会理解每种记忆类型的功能（what），还会明白为什么评分公式存在差异，何时应触发整合，以及如何将 MemoryTool 接入你自己的 Agent。

    来源: Chapter8-Memory-and-Retrieval.md

    从认知科学到 Agent 记忆

    人类记忆蓝图

    在编写任何一行代码之前，HelloAgents 的设计始于第一性原理：人类大脑是如何解决记忆问题的？认知心理学识别出了一种分层记忆系统，具有不同的持续时间、容量和信息类型。感觉记忆以巨大的容量持续 0.5–3 秒；工作记忆在主动处理信息时，可保持 7±2 个项目 15–30 秒；长期记忆可以持续一生，并进一步细分为程序性记忆（技能）、情景记忆（个人事件）和语义记忆（通用知识）。这种层级结构并非随意设定——每一层都针对访问速度、容量和持久性之间不同的权衡进行了优化。

    来源: Chapter8-Memory-and-Retrieval.md

    为什么无状态的 LLM 需要记忆

    大型语言模型本质上是无状态的——每次 API 调用都是一次独立的计算，没有任何状态延续。这导致了四种失败模式：长对话中的上下文丢失（早期信息脱离上下文窗口）、缺乏个性化（模型无法记住用户偏好）、学习能力受限（无法从过去的成功或失败中改进），以及一致性问题（跨轮次出现矛盾的答案）。以下示例清晰地展示了这个问题：

    如果没有显式的记忆层，Agent 就无法跨越会话。记忆系统通过提供跨对话边界持久化、可查询的存储来解决这一问题。

    架构概述：四层设计

    HelloAgents 记忆系统被组织为四个不同的层，每层都有清晰的职责分离。该架构直接受到认知科学层级的启发，但为了可扩展性、可插拔性和操作控制进行了工程化设计。

    HelloAgents Memory System
├── Infrastructure Layer (基础设施层)
│   ├── MemoryManager   — 统一调度与协调
│   ├── MemoryItem      — 标准化记忆数据结构
│   ├── MemoryConfig    — 系统参数配置
│   └── BaseMemory      — 通用接口定义
├── Memory Types Layer (记忆类型层)
│   ├── WorkingMemory   — 临时信息，TTL 管理
│   ├── EpisodicMemory  — 特定事件，时间序列
│   ├── SemanticMemory  — 抽象知识，图谱关系
│   └── PerceptualMemory — 多模态数据
├── Storage Backend Layer (存储后端层)
│   ├── QdrantVectorStore  — 高性能语义检索
│   ├── Neo4jGraphStore    — 知识图谱管理
│   └── SQLiteDocumentStore — 结构化持久化
└── Embedding Service Layer (嵌入服务层)
    ├── DashScopeEmbedding       — 云端 API (阿里)
    ├── LocalTransformerEmbedding — 离线部署
    └── TFIDFEmbedding           — 轻量级备选方案

    四种记忆类型：深入解析

    HelloAgents 中的每种记忆类型都针对不同的信息特征进行了优化——它们具有不同的生命周期、检索策略和评分公式。下表提供了一个对比概述，接下来我们将详细探讨每种类型。

    维度工作记忆情景记忆语义记忆感知记忆
    认知类比短期便签本个人事件日记通用知识库感觉缓冲区
    默认容量约 50 项无限制（持久化）无限制（持久化）动态
    生命周期基于 TTL 过期永久直到被遗忘永久直到被遗忘基于重要性
    存储后端纯内存SQLite + QdrantQdrant + Neo4jSQLite + Qdrant
    检索策略简单关键词 / 过滤结构化过滤 + 向量搜索向量 + 图谱混合跨模态向量
    评分公式仅时间近度(vec_sim×0.8 + recency×0.2) × imp_weight(vec_sim×0.7 + graph_sim×0.3) × imp_weight特定模态
    主要用例当前对话上下文交互历史，学习事件用户偏好，领域规则图像，音频

    工作记忆：Agent 的便签本

    工作记忆作为 Agent 的短期缓冲区，存储当前对话的上下文。它有意限制了容量（默认为 50 项），并使用 TTL（生存时间） 机制自动使过时的条目失效。这反映了人类认知中 7±2 个活跃项目的限制——保持工作集较小可确保快速访问，并防止无关上下文污染检索结果。当项目超出容量或 TTL 时，最不重要的项目会优先被淘汰。

    工作记忆是纯内存型的——不需要 SQLite 或 Qdrant 持久化，因为数据在设计上就是瞬态的。这使得读写操作实际上是 O(1) 的，非常适合活跃对话高频、低延迟的访问模式。

    来源: Chapter8-Memory-and-Retrieval.md

    情景记忆：交互日记

    情景记忆存储特定的交互事件，并附带丰富的上下文元数据——时间戳、会话 ID、重要性评分和事件类型。与工作记忆不同，它专为跨会话的永久持久化而设计，使用 SQLite 存储结构化元数据，使用 Qdrant 进行语义向量搜索。

    检索管道实现了混合两阶段策略：首先，结构化预过滤（时间范围、重要性阈值、会话 ID）缩减候选集；然后，向量语义搜索对剩余候选进行排序。最终得分计算如下：

    score=(vec_sim×0.8+recency×0.2)×(0.8+importance×0.4)\text{score} = (\text{vec\_sim} \times 0.8 + \text{recency} \times 0.2) \times (0.8 + \text{importance} \times 0.4)score=(vec_sim×0.8+recency×0.2)×(0.8+importance×0.4)

    为什么情景记忆将时间近度权重设为 0.2？ 情景记忆记录的是事件，近期事件通常比远期事件更具相关性——“昨天的会议”比“上个月的会议”更具可操作性。0.2 的权重确保时间近度能够在语义相似的事件之间打破平局，而不会压倒主要的语义信号（0.8）。重要性权重的范围 [0.8, 1.2] 被刻意设置得很窄，以防止高重要性项目在不考虑相关性的情况下主导结果。

    来源: Chapter8-Memory-and-Retrieval.md

    语义记忆：知识图谱

    语义记忆是架构上最复杂的类型。它存储的是抽象概念、规则和知识，而不是具体事件——例如，“张三偏好 Python”而不是“星期二，张三说他偏好 Python”。其强大之处来自于双重存储架构：Qdrant 用于语义向量检索，Neo4j 用于知识图谱推理。

    添加记忆时，系统执行三个步骤：(1) 通过统一嵌入服务生成文本嵌入，(2) 使用 spaCy NLP 提取实体和关系，(3) 将向量存储在 Qdrant 中，并将实体/关系同时存储在 Neo4j 中。这意味着每一条语义知识都同时存在于向量表示（用于相似性搜索）和图谱表示（用于关系推理）中。

    混合检索评分公式反映了这种双重特性：

    score=(vec_sim×0.7+graph_sim×0.3)×(0.8+importance×0.4)\text{score} = (\text{vec\_sim} \times 0.7 + \text{graph\_sim} \times 0.3) \times (0.8 + \text{importance} \times 0.4)score=(vec_sim×0.7+graph_sim×0.3)×(0.8+importance×0.4)

    为什么语义记忆将图谱检索权重设为 0.3？ 与情景记忆（时间近度很重要）不同，语义知识是超越时间的——“巴黎是法国的首都”在今天和明年同样正确。取而代之的是关系结构：发现“张三”通过“偏好”边连接到“Python”，增加了纯向量相似性无法提供的推理能力。0.3 的图谱权重捕获了这些隐含关联，而不会覆盖主要的语义匹配信号。

    图谱检索擅长多跳推理——诸如“还有谁与张三偏好同一种语言？”之类的查询需要遍历 (User)→[prefers]→(Language)←[prefers]←(User)，这是原生的图操作，仅靠向量是无法实现的。如果你的用例涉及关系查询，请确保配置了 Neo4j 并且 enable_semantic=True。

    来源: Chapter8-Memory-and-Retrieval.md

    感知记忆：多模态缓冲区

    感知记忆处理多模态数据——图像、音频和其他非文本输入。它采用模态分离的存储策略，为每种模态类型创建独立的向量集合。这避免了维度不匹配问题（图像嵌入和文本嵌入具有不同的维度和语义空间），同时确保了每种模态内的检索准确性。在可用的情况下，通过共享嵌入空间支持跨模态检索（例如，将图像和文本映射到同一向量空间的基于 CLIP 的模型）。

    来源: Chapter8-Memory-and-Retrieval.md

    MemoryTool：统一接口

    MemoryTool 是 Agent 与所有记忆类型交互的单一入口点。它遵循“统一入口，分布处理”模式——execute() 方法接受一个 action 参数，并分派给相应的内部方法和记忆类型。这种设计意味着 Agent 永远不需要知道哪个记忆后端存储了它们的数据；它们只需调用 execute("add", ...) 或 execute("search", ...)。

    来源: Chapter8-Memory-and-Retrieval.md

    核心操作：add

    add 操作将感知到的信息编码为特定的记忆类型。每个记忆项都附带丰富的上下文元数据——时间戳、重要性评分、会话 ID——这些元数据为后续的智能检索和评分提供动力。

    来源: Chapter8-Memory-and-Retrieval.md

    核心操作：search

    search 操作使用语义相似性检索记忆，并支持对记忆类型和最低重要性的可选过滤。它支持单数（memory_type）和复数（memory_types）参数形式，以提供灵活性。

    来源: Chapter8-Memory-and-Retrieval.md

    核心操作：forget

    遗忘不是缺陷——而是特性。forget 操作实现了三种策略，映射了人类认知遗忘的不同方面：

    策略机制类比
    importance_based删除低于重要性阈值的记忆遗忘琐事而记住关键事件
    time_based删除超过 max_age_days 的记忆旧记忆随时间逐渐消退
    capacity_based当数量超限时，淘汰最不重要的记忆为新信息腾出空间

    来源: Chapter8-Memory-and-Retrieval.md

    核心操作：consolidate

    consolidate 操作直接借鉴自神经科学——它模拟了人类大脑在睡眠期间将短期记忆转移至长期存储的过程。在 HelloAgents 中，这意味着根据重要性阈值，将重要的工作记忆（或情景记忆）提升为更持久的记忆类型。

    工作记忆→情景记忆的默认阈值为 0.7，这是一个务实的平衡：太低会使情景存储充满噪音；太高则会丢失有价值的上下文。情景记忆→语义记忆更高的 0.8 阈值反映了语义记忆存储的是抽象知识这一事实——只有经过充分验证、反复确认的信息才应被提升到这一永久存储中。

    来源: Chapter8-Memory-and-Retrieval.md

    MemoryManager：编排器

    在 MemoryTool 之下是 MemoryManager，这是一个协调器，负责实例化并分派给相应的记忆类型模块。MemoryTool 处理面向用户的参数解析和结果格式化；MemoryManager 处理实际的存储和检索逻辑。这种职责分离意味着你可以替换整个存储后端，而无需触碰工具接口。

    请注意，感知记忆默认是禁用的（enable_perceptual=False），因为它需要额外的多模态基础设施。仅当你的用例明确需要图像或音频存储时才启用它。

    来源: Chapter8-Memory-and-Retrieval.md

    评分公式对比：情景记忆 vs. 语义记忆

    情景记忆和语义记忆的不同评分公式并非随意设定——它们直接反映了每种类型存储的信息的本质。下表分解了其背后的基本原理：

    组成部分情景权重语义权重原理
    向量相似度0.80.7两者都优先考虑语义相关性；情景记忆略高，因为事件的结构化程度较低
    时间近度0.2—近期事件很重要；永恒的知识则不然
    图谱相似度—0.3关系推理为抽象知识增加了独特价值
    重要性范围[0.8, 1.2][0.8, 1.2]窄范围防止重要性压倒相关性

    这种设计确保了情景记忆自然地呈现近期相关的记忆，而语义记忆则利用关系结构来发现概念之间的隐含关联。

    后续内容

    记忆系统赋予了 Agent 跨会话的持久性，但它没有解决外部知识的问题——即 LLM 从未训练过的信息。这正是 RAG（检索增强生成）管道的职责所在，它在查询时从外部知识库中检索相关文档。RAG 和记忆是互补的：记忆存储的是Agent 经历过的内容，而 RAG 提供的是Agent 需要知道的内容。完整的故事请参阅 RAG 管道与检索 ，关于记忆和 RAG 结果如何组合成连贯的提示词输入给 LLM，请参阅 使用 ContextBuilder 进行上下文工程 。
