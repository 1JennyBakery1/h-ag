    面向 Agent 的 LLM 基础

    24 分钟等级: 进阶

    大语言模型是每个现代 Agent 核心的认知引擎。本页将对 LLM 的内部运作机制进行结构化的深度剖析——从语言建模的数学基础，到驱动当今模型的 Transformer 架构，再到直接影响 Agent 设计的实际交互模式与模型选择策略。理解这些基础知识对于任何构建 Agent 的人来说都至关重要：它指导你如何编写提示词、选择模型、诊断故障以及构建可靠的系统。

    从统计语言模型到神经网络

    语言建模是计算词序列概率的基础任务。一个好的语言模型能告诉我们哪些句子自然、哪些不自然——在 Agent 系统中，它决定了每个生成的动作、响应和计划的质量与连贯性。从统计方法到神经方法的演进，揭示了至今仍在影响 LLM 设计的核心挑战。

    N-gram 模型与马尔可夫假设

    概率的链式法则将句子概率分解为条件概率的乘积：P(S) = P(w₁)·P(w₂|w₁)·P(w₃|w₁,w₂)⋯P(wₘ|w₁,…,wₘ₋₁)。然而，从有限语料库中估计长条件历史是不可行的。马尔可夫假设通过仅使用前 n−1 个词来近似每个条件概率，从而解决了这个问题，并由此产生了 N-gram 模型。Bigram（N=2）模型将 P(wᵢ|w₁,…,wᵢ₋₁) 简化为 P(wᵢ|wᵢ₋₁)，通过最大似然估计进行计算：

    P(wi∣wi−1)=Count(wi−1,wi)Count(wi−1)P(w_i|w_{i-1}) = \frac{\text{Count}(w_{i-1}, w_i)}{\text{Count}(w_{i-1})}P(wi​∣wi−1​)=Count(wi−1​)Count(wi−1​,wi​)​

    配套代码使用微型语料库 "datawhale agent learns datawhale agent works" 演示了这一过程，计算出 P("datawhale agent learns") ≈ 0.333 × 1.0 × 0.5 ≈ 0.167。尽管 N-gram 简洁优雅，但它存在两个致命缺陷：数据稀疏（未观测到的序列概率为零）和泛化能力差（它将词视为原子符号，缺乏语义相似性——“agent learns”无法为“robot learns”提供参考）。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L7-L105), N_gram.py

    词嵌入与神经语言模型

    突破来自于将词表示为高维语义空间中的连续向量（词嵌入），在语义上相似的词会聚集在一起。Bengio 等人的前馈神经语言模型（2003年）引入了这种两步范式：首先将每个词映射为稠密向量，然后学习一个从上下文向量到下一个词概率分布的神经函数。这解决了 N-gram 的泛化问题——著名的例子 vector('King') − vector('Man') + vector('Woman') ≈ vector('Queen') 展示了向量算术如何捕捉由余弦相似度衡量的类比关系。然而，与 N-gram 一样，该模型仍然在固定上下文窗口上运行，无法捕捉超出前 n−1 个词的依赖关系。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L107-L165)

    RNN 与 LSTM：捕捉变长上下文

    循环神经网络 (RNN) 引入了作为短期记忆的隐藏状态向量，允许模型通过传递所有先前输入的压缩表示来处理任意长度的序列。LSTM 通过细胞状态和三个门（遗忘门、输入门、输出门）进一步完善了这一点，选择性地保留或丢弃信息，从而缓解了长期依赖问题（在多个时间步中梯度消失）。然而，RNN 依然面临一个关键瓶颈：顺序计算——步骤 t 必须等待步骤 t−1 完成，使得并行化无法实现，在长序列上训练缓慢。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L167-L185)

    Transformer 架构：现代 LLM 的基石

    由 Vaswani 等人于 2017 年提出的 Transformer，通过纯注意力机制架构解决了顺序计算瓶颈。其设计是当今驱动 Agent 的每个 LLM 的直接鼻祖。

    编码器-解码器结构

    原始的 Transformer 遵循为机器翻译设计的编码器-解码器架构。编码器读取并表示整个输入序列；解码器以自回归方式生成输出序列，并通过交叉注意力参考编码器的表示。完整的代码骨架——从 EncoderLayer 和 DecoderLayer 到完整的 Transformer 类——在配套代码中实现，每个子层均采用 Post-LN（残差添加后的层归一化）。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L186-L285), Transformer.py

    自注意力与多头注意力

    自注意力是一种让序列中的每个词元都能关注其他所有词元的机制，从而计算具有上下文感知的表示。对于每个词元，派生出三个可学习的角色向量：查询 ——该词元正在寻找什么；键 ——该词元作为匹配信号提供什么；值 ——该词元贡献的实际内容。缩放点积注意力公式如下：

    Attention(Q,K,V)=softmax(QKTdk)V\text{Attention}(Q, K, V) = \text{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)VAttention(Q,K,V)=softmax(dk​​QKT​)V

    多头注意力通过在 h 个并行头上拆分 Q、K、V 来扩展此机制，每个头在独立的子空间中运行。这使得模型能够同时捕捉不同的关系类型（例如，句法、语义、位置）。所有头的输出被拼接并进行线性投影。配套代码中 MultiHeadAttention 的实现包含了 split_heads → scaled_dot_product_attention → combine_heads → 输出投影，并带有针对填充和因果（前瞻）约束的可选掩码。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L287-L381), Transformer.py

    前馈网络、残差连接与位置编码

    除了注意力机制，每个 Transformer 层还包含一个逐位置前馈网络 (FFN)，对每个词元向量独立应用带有 ReLU 激活的两次线性变换，通常将维度从 d_model 扩展到 4 × d_model 再还原。这种“先扩展后压缩”的模式从注意力聚合的表示中提取非线性特征。残差连接 绕过每个子层以缓解梯度消失，层归一化 通过对每个样本的特征进行归一化来稳定训练。位置编码 通过固定的正弦函数注入顺序信息——偶数维度使用正弦，奇数维度使用余弦——确保模型能够区分 "agent learns" 和 "learns agent"，尽管注意力机制具有排列等变性。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L383-L474), Transformer.py

    纯解码器架构：为何 GPT 舍弃了编码器

    虽然原始的 Transformer 同时使用了编码器和解码器，但 OpenAI 的 GPT 做出了一个关键简化：完全舍弃编码器，仅保留解码器。这种纯解码器架构以自回归模式运行——给定一个提示词，它预测下一个词元，将其追加，然后重复。掩码自注意力机制阻止每个位置关注未来的词元，确保因果生成。此设计为 Agent 提供了三个关键优势：

    优势解释对 Agent 的意义
    统一的训练目标“预测下一个词元”适用于任何原始文本——无需标签海量预训练规模 → 广泛的世界知识
    结构简单组件更少 → 更容易扩展至数十亿参数更大的模型展现出涌现的推理与指令遵循能力
    天然适配生成自回归解码匹配对话、规划和工具使用模式直接适用于 Agent 的思考-动作循环

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L476-L508)

    与 LLM 交互：提示词工程与分词

    理解如何与 LLM 通信与理解其架构同等重要。两个交互层——提示词工程与分词——直接决定了 Agent 的行为、成本和可靠性。

    采样参数：控制输出多样性

    LLM 通过从词汇表的概率分布中采样来生成文本。三个关键参数重塑了此分布：

    参数机制效果典型 Agent 用途
    Temperature在 softmax 前将 logits 除以 TT↓ = 更尖锐/确定性；T↑ = 更平坦/多样性事实性任务使用低 T；创造性任务使用高 T
    Top-k仅保留概率最高的 k 个词元将候选池限制为前 k 个防止选中低概率词元
    Top-p (Nucleus)保留累积概率 ≥ p 的最小词元集合动态适应分布形态对于偏斜分布优于 Top-k

    这些参数以级联顺序应用：Temperature 调整完整分布 → Top-k 过滤候选 → Top-p 进一步缩小核集。设置 Temperature=0 或 Top-k=1 会强制贪婪解码，使其他参数失效。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L512-L543)

    提示词策略：零样本、单样本、少样本与思维链

    提示词中提供的示例数量和类型极大地影响输出质量。零样本提示完全依赖模型的预训练知识——对简单分类有效，但对复杂任务表现脆弱。单样本和少样本提示提供 1 个或 N 个示例来展示预期的输入输出格式，利用模型的上下文学习能力。思维链 提示在示例中添加推理步骤，或附加“让我们逐步思考”，强制模型分解复杂问题——这对于需要多步规划和工具编排的 Agent 尤为关键。

    专门针对 Agent，另外两项技术是基础：角色扮演（为模型分配一个角色，如“你是一位资深 Python 专家”）约束响应风格和知识范围；上下文示例（提供结构化的输入输出对）教会模型特定任务的格式，例如输出包含确切字段名称的 JSON。这两种技术成为了 Agent 系统提示词的构建模块。

    在设计 Agent 系统提示词时，请将角色扮演与少样本 CoT 示例结合使用。这种双重策略同时约束了模型的行为边界，并教会其多步动作序列所需的推理模式——这是任何 Agent 循环的核心。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L547-L663)

    分词：文本与模型之间的桥梁

    在文本到达模型之前，分词器 将其转换为整数词元 ID 序列。朴素策略——基于词的（词汇爆炸 + 未登录词）和基于字符的（单个词元无语义）——均显不足。现代 LLM 使用子词分词，最常见的是字节对编码 (BPE)，它迭代合并最频繁的相邻词元对，直到达到目标词汇表大小。配套代码演示了此过程：从字符 {h, u, g, p, n, b, </w>} 开始，BPE 在 4 次迭代中合并 (u,g)→ug，(ug,</w>)→ug</w>，(u,n)→un，(un,</w>)→un</w>。

    对于 Agent 开发者，分词有三个实际影响：上下文窗口限制以词元而非字符计算——同一句话在不同语言或分词器下消耗的词元数量可能大不相同；API 成本按词元计费；模型异常通常源于分词的怪癖（例如，2+2 与 2 + 2 的分词结果可能不同，导致算术错误）。诸如 WordPiece（被 BERT 使用，选择最大化语言模型似然的合并）和 SentencePiece（被 Llama 使用，将空格视为常规字符以实现与语言无关的分词）等变体针对不同的权衡进行了设计。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L664-L763), BPE.py

    使用 Hugging Face 本地调用开源模型

    Hugging Face transformers 库提供了加载和运行预训练模型的标准化接口。配套代码使用 Qwen/Qwen1.5-0.5B-Chat——一个 5 亿参数的聊天模型——演示了完整流程：加载 AutoModelForCausalLM 和 AutoTokenizer → 使用 apply_chat_template 格式化消息 → 将文本编码为词元 ID → 使用 max_new_tokens 调用 model.generate() → 将输出词元 ID 解码回文本。这种本地部署模式对于需要数据隐私、离线操作或成本控制的 Agent 至关重要。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L764-L856), Qwen.py

    Agent 开发的模型选择

    为 Agent 选择 LLM 是一个多维度的权衡，绝非简单的“选最强的”。下表列出了关键的决策维度：

    维度核心问题权衡
    性能与能力模型是否擅长 Agent 所需的特定任务？通用基准 ≠ 领域特定性能
    成本每词元的 API 成本或本地硬件成本是多少？API 便利性 vs. 本地部署投资
    速度 (延迟)模型响应速度能否满足实时交互需求？更大的模型更慢；蒸馏/更小的模型更快
    上下文窗口模型能否在一次处理中容纳所有必要上下文？长文档 Agent 需要 128K+；简单聊天 Agent 需求较小
    部署模式API vs. 本地？云端 vs. 边缘？数据敏感性、合规性和离线需求
    生态系统与工具模型是否有 LangChain、LlamaIndex 等支持？更丰富的生态系统 → 更快的开发速度
    微调能力能否在领域数据上定制模型？对专门的 Agent 行为至关重要
    安全与伦理模型如何处理偏见、毒性和幻觉？企业级 Agent 需要强大的安全保证

    在闭源方面，OpenAI GPT（多模态前沿）、Google Gemini（原生多模态 + 长上下文）和 Anthropic Claude（安全优先 + 长文档）代表了领先选项。中国提供商如百度文心、腾讯混元和月之暗面提供了强大的中文能力。在开源方面，Meta Llama（广泛采用，社区强大）、Mistral AI（小而精的设计理念）以及中国的 Qwen 和 ChatGLM 等模型提供了完全的定制自由。闭源模型提供“开箱即用”的便利；开源模型提供“随心定制”的控制。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L858-L896)

    缩放定律与 LLM 的局限性

    缩放定律：规模带来可预测的能力

    缩放定律揭示了模型性能（以损失衡量）与三个因素之间的幂律关系：参数量、训练数据量和计算预算。在双对数空间中，每个因素都产生平滑、可预测的改进曲线。Chinchilla 缩放定律（DeepMind，2022年）完善了这一见解：对于给定的计算预算，参数量和数据量之间存在一个最优比例——仅仅增加模型大小而不按比例增加数据是次优的。缩放最引人注目的后果是涌现能力——如思维链推理、指令遵循和上下文学习等能力在特定规模阈值处突然出现，而在较小模型中是不存在的。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L898-L910)

    幻觉：Agent 最大的可靠性威胁

    幻觉发生在 LLM 生成与事实、输入上下文或内部一致性相矛盾的内容时——过度自信地编造信息，而不是承认不确定性。有三类幻觉与 Agent 特别相关：事实性幻觉（与现实事实矛盾）、忠实性幻觉（歪曲来源文本）和内在幻觉（与 Agent 自身先前的陈述矛盾）。根本原因包括嘈杂的训练数据、下一个词元预测的自回归性质（缺乏内置的事实核查）以及对复杂任务的有限推理能力。

    缓解策略在三个层面运作：数据层面（高质量策划、RLHF 对齐）；模型层面（架构改进、不确定性表达）；以及推理层面——最显著的是检索增强生成 (RAG)，将生成建立在检索到的外部证据上，带验证的多步推理，以及外部工具调用（搜索引擎、计算器、代码解释器）。对于 Agent，最后一类尤其强大：调用工具获取实时、经过验证的信息的能力，直接在生成时对抗幻觉。

    在构建 Agent 时，应将幻觉缓解视为系统级关注点，而非模型级问题。结合 RAG 进行事实锚定、结构化输出解析确保忠实性、以及工具调用进行实时验证——每一层都能捕获其他层遗漏的问题。

    来源: [第三章 大语言模型基础.md](docs/chapter3/第三章 大语言模型基础.md#L912-L933)

    将 LLM 基础知识与 Agent 设计相连

    本页中的每个概念都与 Agent 架构直接相关。纯解码器自回归范式塑造了 ReAct 等Agent核心的思考-动作-观察循环。提示词工程技术——尤其是 CoT 和角色扮演——成为了治理 Agent 行为的系统提示词设计模式。分词约束决定了上下文窗口管理策略。缩放定律和幻觉局限定义了Agent必须在其内运行的可靠性边界，从而驱动了对外部记忆 (RAG)、工具使用和验证机制的需求。

    要了解这些基础知识如何转化为具体的 Agent 范式，请继续阅读 经典 Agent 范式（ReAct、Plan-and-Solve、Reflection） 。有关在生产中部署模型和工程提示词的实践方面，请参阅 上下文工程 和 记忆系统与 RAG 。
